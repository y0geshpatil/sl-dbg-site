Why sl-dbg

Debuggers were built for humans staring at an IDE. AI agents need something else.

Inspect a paused program instead of guessing from source alone. The same debugger operations are available to your terminal and an MCP-aware coding agent.

⚡

Stateless wire protocol

No interactive prompt required. Target a session, issue a command, and inspect the result before taking the next step.

{ }

Structured debugger output

Use command-line flags from a shell or structured tool arguments over MCP. JSON results are ready for scripts and agents.

⇄

Built on DAP

Reuses the same Debug Adapter Protocol VS Code uses, so it speaks to mature, well-tested adapters out of the box.

★

MCP-native

Debugger operations are exposed as Model Context Protocol tools. Register with your client after installing a language adapter.

⌘

Daemon-backed

A tiny local daemon keeps debug sessions alive across invocations, so successive commands stay fast and stateful where it matters.

∅

One CLI binary

The CLI needs no Go compiler. Debugging still needs the target language runtime and its separately installed adapter.

Install

Install the CLI, then your language adapter.

y0geshpatil/sl-dbg is Apache-2.0. Use macOS or Linux on amd64 or arm64, with Bash, curl, tar, and sha256sum or shasum. Public releases need no GitHub login. Start-to-finish setup and troubleshooting →

install.sh — recommended
$ curl -fsSL https://raw.githubusercontent.com/y0geshpatil/sl-dbg/main/scripts/install.sh | bash

Installs the latest stable release to ~/.local/bin without sudo and verifies its SHA-256 checksum. The script runs code on your machine; read it first, or use the download-and-review instructions in the guide.

make the CLI available in this shell
export PATH="$HOME/.local/bin:$PATH"
command -v sl-dbg
sl-dbg version

Keep that PATH line in ~/.zshrc (zsh) or ~/.bashrc (interactive Bash). Already installed under /usr/local/bin? Check type -a sl-dbg so an older copy does not take precedence.

install.sh — example version pin
$ curl -fsSL https://raw.githubusercontent.com/y0geshpatil/sl-dbg/main/scripts/install.sh | bash -s -- v0.5.4

Replace the example with a tag from Releases. This pins the binary, not the installer script or language adapters. v0.5.4 does not ship a Java adapter JAR.

install.sh — explicit destination
$ curl -fsSL https://raw.githubusercontent.com/y0geshpatil/sl-dbg/main/scripts/install.sh \
    | INSTALL_DIR="$HOME/.local/bin" bash

Set INSTALL_DIR on bash, not curl. Choose a directory you own, and add that same directory to your PATH. Do not run the installer with sudo.

manual tarball
# 1. Grab the tarball for your OS/arch from:
https://github.com/y0geshpatil/sl-dbg/releases/latest

# 2. Download the matching checksums file.
# 3. Verify the archive BEFORE extracting it.
# 4. Install the binary into a directory you own.

Choose the archive for your OS and architecture, not just the first download. Manual download commands → Checksums detect corruption; they are not release signatures.

remove the CLI and detected MCP registrations
# First finish your sessions and close MCP clients. See the uninstall guide.
$ curl -fsSL https://raw.githubusercontent.com/y0geshpatil/sl-dbg/main/scripts/uninstall.sh | bash

# Only the binary, keep MCP entries:
$ curl -fsSL https://raw.githubusercontent.com/y0geshpatil/sl-dbg/main/scripts/uninstall.sh | bash -s -- --keep-mcp

# Or, surgically, just one agent:
$ sl-dbg mcp uninstall claude   # or cursor | vscode | codex | copilot | all
$ sl-dbg mcp uninstall all --dry-run   # preview first

Use the same INSTALL_DIR as installation. The script does not stop a running daemon or remove adapters, logs, caches, or backups. Workspace registrations need cleanup in each workspace. Update and uninstall safely →

Install language adapters

No adapter is bundled. They live in their own ecosystems and you only install the ones you need.

Python
sl-dbg install-adapter python

Needs Python and pip. For a first session, use the isolated virtual environment below to avoid system-Python permission restrictions.

Go
sl-dbg install-adapter go

Needs a Go toolchain compatible with current Delve. Installs dlv via go install; ensure its bin directory is on PATH.

Java
sl-dbg install-adapter java

Needs JDK 11+. The v0.5.4 release has no adapter JAR; use the source-build instructions or a later release that includes it.

All
sl-dbg install-adapter all

Attempts all three; missing prerequisites can fail the command. Start with only the language you need.

Quickstart

Pause a small Python program and inspect its total.

After installing the CLI, run this in Bash or zsh. It creates a fresh scratch directory and virtual environment. Python with venv support is required. Full walkthrough and expected results →

Debug a Python script
python — isolated setup
demo_dir="$(mktemp -d)"
cd "$demo_dir"
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install debugpy
printf '%s\n' 'prices = [10, 20, 30]' 'discount = 5' \
  'total = sum(prices) - discount' 'print(total)' > sl-dbg-demo.py

Keep this shell active. If a daemon is already running from another Python environment, finish its sessions before running sl-dbg daemon stop; the next command starts it with this shell’s PATH.

python — stop before print, inspect, then clean up
$ sl-dbg start --lang python --program ./sl-dbg-demo.py --stop-on-entry
$ sl-dbg break sl-dbg-demo.py:4
$ sl-dbg continue
$ sl-dbg locals
# Look for total = 55 in the paused frame's variables.
$ sl-dbg stop
Attach to a running JVM

Requires an installed Java adapter, your application’s source, and a JVM started with a localhost-only JDWP listener on port 5005. Replace the class and line below with your own; do not expose JDWP publicly.

java — attach to JDWP
$ sl-dbg attach --lang java --host 127.0.0.1 --port 5005
$ sl-dbg break com.example.OrderService:128
$ sl-dbg threads
$ sl-dbg stack
Debug Go with Delve

Requires Go, Delve, and your own Go module. Run from its root and replace the package path and function name below.

go — package debug
$ sl-dbg start --lang go --program ./cmd/server --stop-on-entry
$ sl-dbg break-fn main.handleRequest
$ sl-dbg continue

For AI agents

Drop sl-dbg into Claude Desktop, Cursor, or any MCP client.

sl-dbg speaks Model Context Protocol over stdio. Install a language adapter first, then preview and register one client. Registration edits that client’s configuration; it does not install the client.

On v0.5.4, VS Code and Copilot registration use older formats. Use the manual configuration examples for those clients until a release includes the registration fixes.

Run the example from the directory containing sl-dbg-demo.py. The program allowlist matches the target file, not python3; a bare registration can connect but reject a script launch.

1 · Register with one command

preview first, then choose your agent
$ sl-dbg mcp install claude \
    --allow-program "$PWD/sl-dbg-demo.py" --dry-run
# After reviewing the preview, register:
$ sl-dbg mcp install claude \
    --allow-program "$PWD/sl-dbg-demo.py"
# Replace claude with cursor, vscode, codex, or copilot.
# claude means Claude Desktop; vscode is workspace-scoped.

Restart your client after registration and confirm it lists sl-dbg’s tools. Existing files receive a timestamped backup; replacing an existing entry requires --force. sl-dbg mcp install --print prints configuration without editing files. PATH, source-root, and client setup details →

2 · Limit the agent’s access

preview inspection-only registration
$ sl-dbg mcp install claude --read-only --dry-run
# Remove --dry-run to register. Use --force only to replace
# an existing entry you have reviewed.

Registration uses --safe. Read-only mode hides mutating tools, including starting a new session; it is not the mode for the first-session tutorial. These controls are not an OS sandbox: only debug code you trust, and review the security limits.

What an agent sees

  • Tools — debugger operations (start, attach, break, continue, locals, eval, watch, …) with structured input schemas. Policy can restrict their use.
  • Resources — sl-dbg://sessions, sl-dbg://events, sl-dbg://adapters for live state without spending a tool call.
  • Prompts — turnkey templates like diagnose_loop_bug, trace_call_path, watch_then_continue.

Reference

The full command surface, at a glance.

Lifecycle

  • start — launch a program under the debugger
  • attach — attach to a running process or DAP server
  • stop — terminate a session
  • restart — restart the current session
  • sessions — list active sessions

Breakpoints

  • break — set line breakpoint (file:line or Class:line)
  • break-fn — set function breakpoint
  • breaks — list breakpoints + hit counts
  • unbreak — remove breakpoint(s) by id
  • --if, --hit, --log, --once modifiers

Stepping

  • continue — resume execution
  • step — step into
  • next — step over · finish — step out
  • until <line> — run until a line in the current file
  • pause — break a running program

Inspection

  • stack · threads
  • locals · globals
  • eval · set
  • print — pretty-printed deep inspect
  • fields — drill into a variable ref
  • snapshot — full pause snapshot

Watches & events

  • watch --add <expr> · watch · watch --remove <id>
  • events — recent DAP events
  • output — captured stdout/stderr from debuggee
  • Watches are persisted across sessions for the same program.

Meta

  • adapters — list installed adapters
  • install-adapter <lang|all>
  • daemon stop|status|logs
  • version
  • mcp — speak MCP over stdio

Debugger commands support JSON output; use --json explicitly in scripts. Run a command with --help for the flags supported by your installed version.

FAQ

Honest answers.

Is the source code open?

Yes. Source lives at github.com/y0geshpatil/sl-dbg under Apache-2.0. Release build settings are recorded in the repository; a local build is not guaranteed to be byte-identical.

Do I need a GitHub account to install?

No. Published release downloads are public. If installation returns HTTP 403 or 404, check the release tag, network access, and GitHub API rate limits. See troubleshooting.

How do I do a security review?

Review the source, install scripts, release SHA-256 checksums, MCP tool surface, and threat model. Checksums are not signatures. Report vulnerabilities privately per SECURITY.md, not in public issues.

What state lives on disk?

The binary, language adapters, daemon files, logs, watch data, and any MCP configuration backups may remain on disk. Paths depend on your environment. Do not delete runtime files while sessions are active; see cleanup guidance.

What if my SESSION_NOT_FOUND errors come and go?

Check sl-dbg sessions and the session ID you passed. Sessions live in the daemon and do not survive a restart or reboot. Start a new session if the old one no longer exists.

How do I uninstall?

Finish debug sessions, close MCP clients, and follow the uninstall guide. Match the original install directory and preview MCP cleanup before removing the binary. Adapters and cached data are separate.

Can I run multiple sessions at once?

Yes. Pass --session <id> to target one explicitly. Without it, commands use the default session, normally the most recently started.
